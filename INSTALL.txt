LiveMap v5.1.0 - Install Package
================================

Contents:
  LiveMap/                     -> phpVMS module (copy to <phpvms-root>/modules/LiveMap/)
  live_map.blade.php           -> theme file (one line, copy into each theme in use)

New in v5.1.0:

  Compact look of 4.7.9 again (flight board "Active flights | Planned" at
  the top, detail box like the 4.7.9 crew pass) on the 5.0 technology.

  - Source "Both" (Admin -> Live Map): AeroACARS Live plus phpVMS. The same
    pilot with the same callsign counts as ONE flight (registration, PIREP
    link and logo come from the PIREP). If one source fails, the other is
    shown with a notice. Optional "AeroACARS VA prefix" limits the list to
    one VA.
  - Aircraft symbols by class (seven silhouettes), nose in flight direction,
    smaller on the ground.
  - Own Leaflet 1.9.4 (pinned, with integrity check): works under Seven,
    SPTheme and Disposable_v3 without depending on the theme's Leaflet.
    Other themes: copy live_map.blade.php into their widgets/ folder.
  - The views live inside the module. The theme file is a single @include.
    live_map_styles.blade.php and live_map_scripts.blade.php are NO LONGER
    NEEDED (from 5.1 on). Later updates only touch modules/LiveMap.
  - Cleaner map (stacking order, "+n" for stacked flights, VATSIM and IVAO
    boxes side by side), zooming ends "Follow", no overlapping controls at
    any window size, narrow mode below 760 px widget width.
  - Dark mode follows the theme (data-bs-theme / data-theme) or is set to
    light/dark in the settings. Height follows the window between a
    minimum and maximum you set. Without a CARTO key the default map is
    OpenStreetMap.
  - Flight panel position (Admin -> Live Map, replaces "Layout mode"):
    top (collapsible over the map), bottom (fixed full-width table below
    the map, outside the map area) or off. Updating from 4.7.x without the
    new setting derives the position from the old keys: old_style on, or
    show_top_flights_panel explicitly off = off, otherwise top. A new
    install starts at bottom (recommended). The old keys are still written.
  - Detail box folds to its header row when a box beside it does not fit
    (callsign opens it again); narrow board without logos; board header
    with icons as in 4.7.9. Controller boxes and sector labels sit below
    the controls (board, zoom, tools), as in 4.7.9.
  - VATSIM/IVAO controllers the VATSIM Radar way: voice-frequency gate
    117-137 MHz (ATIS outside it and observers without a voice frequency
    do not count; observer on a voice frequency at a real position = box
    with a grey "O"), controllers grouped by resolved facility, FIR
    assignment by longest prefix, sub-sectors, collective positions from
    [UIRs], _FSS = oceanic area. IVAO sectors also appear without VATSIM.
    Fetches have a timeout and are retried (large data files after 5 min); sources come via
    jsDelivr; overlapping sector labels are nudged or hidden.
  - NOT adopted: TRACON areas of the SimAware TRACON Project (measured
    03.11.2026: the 1.77 MB release asset has no CORS header on GitHub,
    jsDelivr has 1389 single files / 4.4 MB without a prefix index; only a
    fetch through every VA's server would remain) - the green TRACON
    shield stays. VATGlasses altitude sectors: 28 MB, CC BY-NC-SA,
    third-party service.
  - Data: VATSpy Data Project (vatsimnetwork/vatspy-data-project); rules
    for controller/FIR assignment after VATSIM Radar (CC BY-NC 4.0).
  - New settings: flight panel position, source "Both", VA prefix, light/dark/auto, minimum and
    maximum height, callsign labels on/off.

  - Admin -> Live Map now opens for every staff member with access to the
    admin panel (role "admin" or the permission "Admin Panel"), not only
    for the role "admin".

  UPGRADE from 5.0 or older: follow "Installation" at the end of this
  file - everything is done with FTP and the phpVMS admin, no SSH.

New in v5.0.0:

  Flight data now always comes through the module (/livemap/api/fluege,
  8 s buffer) instead of the phpVMS core helper render_live_map. The
  source is a setting under Admin -> Live Map:

  - phpVMS (default): the running PIREPs of this site, as before.
  - AeroACARS Live: the same flights, fields and phases as the admin
    web app on live.kant.ovh. Needs a read key; the key stays on the
    server and is only ever sent to https://live.kant.ovh.

  Without a stored source the map uses phpVMS - nothing to do after the
  upgrade. Only a fixed field list leaves the server, pilot names are
  shortened ("Kenji M.").

  New layout: flight list on the left, flight detail on the right, tools
  top right (network, weather, map, follow); below 760 px widget width
  list and detail open as sheets from the bottom. The map fills the
  window (440-1400 px). The "Mobile Flights Button" colours and the
  height argument of the widget call are no longer used.

  Fixed: below zoom 3 all aircraft disappeared; tracks and markers of a
  flight across 180 degrees stay in the world copy currently shown; a
  short outage of the source keeps the last good state (marked stale).

  UPGRADE: the module adds routes. After copying, click
  Admin -> Maintenance -> "Clear all caches" (this also rebuilds a cached
  route list), otherwise /livemap/api/fluege answers 404 and the map
  stays empty.

Fixed in v4.7.7 (reported by ProAvia):

  An aircraft sat at 0/0 in the Gulf of Guinea, showing "100%" progress
  and 7247 of 2408 nm. Not pilot error: a simulator reports 0/0 while it
  does not yet know where the aircraft is - P3D before the airport is
  loaded, MSFS while loading. phpVMS accepts that like any other ACARS
  position; in the `acars` table `lat` and `lon` even DEFAULT to 0.00000.

  One row, four symptoms: the aircraft in the Atlantic, "distance flown"
  = departure -> 0/0 (about 7,200 nm from KSEA), progress at 100%, and
  the whole map pulled out to half the world, because the core centres
  on the bounds of all flight markers and the phantom point is in them.

  Such positions now count as NO position: no marker, no distance, no
  progress, no auto-zoom. The flight stays in the list showing "-" and a
  note that the sim has not reported a position yet. As soon as a real
  position arrives, everything is back on the next refresh.

  Two more places, same cause, same release: the flown track drawn when
  you click a flight ran across the Atlantic if a single 0/0 point sat
  in its log, and selecting a flight without a position left the
  previous flight's route line on the map.

  Only BOTH coordinates near zero count as bogus - 0N/9.7E is Libreville.

Fixed in v4.7.4 (reported by ProAvia):

  "API KEY REQUIRED" still showed on page load even with a key stored -
  and went away after switching map style. Cause: TWO base layers. The
  widget passes providers:{'CartoDB.Positron':{}} to render_live_map,
  and the phpVMS core builds its OWN tile layer from that, via the
  leaflet-providers catalog - which has no slot for a key. No module
  code could reach it, and it sat on top.

  The key is now attached at L.TileLayer.prototype.getTileUrl, the one
  place every tile passes through, whoever created the layer. The
  duplicate core layer is also removed - it was fetching every tile
  twice, i.e. double your CARTO quota.

  If you are on 4.7.0-4.7.3 and see the watermark on load, this is it.

Where to put the CARTO key - two ways:

  A) Admin -> Live Map -> CARTO Basemaps API Key, then Save.
     This is the normal way and it wins over .env.

  B) In your .env, useful before anyone opens the settings page or when
     you deploy by file only:

         CARTO_API_KEY=cb1_...

     Then click Admin -> Maintenance -> "Clear all caches" so the value
     is read.

  Precedence: a key entered in the admin page ALWAYS wins over .env -
  including one you deliberately removed there. The .env value applies
  only while nobody has set one in the admin page. So if you cleared the
  key on the page and it is still active, remove the .env line as well.

  From v4.7.3 the status box says which of the two the active key comes
  from, so you no longer have to guess.

What this release fixes (IMPORTANT if you run v4.7.0 or v4.7.1):

  The CARTO API key was never stored. You could paste it, the page said
  it was saved - and nothing was written. Three separate faults:

  1) The key had no entry in the module's settings definitions, and only
     defined settings are persisted. Everything else was dropped on save,
     silently.

     Consequence: If you entered a key in v4.7.0 or v4.7.1 and the map
     still shows the watermark, that is why. Enter it again after this
     upgrade - it will stick this time.

  2) "Remove Currently Stored API Key On Save" had no effect, for the
     same reason.

  3) Opening the settings page a second time returned HTTP 500. The
     cached key-verification verdict was written without its primary
     key, so the second write collided with the first
     ("Duplicate entry '' for key 'PRIMARY'").

     This one hits every installation that saved settings twice, whether
     or not you use CARTO.

  If your key lives in .env instead: an entry made through the admin UI
  now wins over CARTO_API_KEY, including an entry you deliberately
  cleared. The .env value only applies while nobody has set one - so
  removing the key in the UI really removes it.

What the 4.7 line added (v4.7.0 + v4.7.1):

  CARTO requires a key since 26 Aug 2026. Its RASTER service - which the
  "Carto Light" and "Carto Dark" basemaps use - stamps "API KEY REQUIRED"
  across every tile without one. The vector service is not affected yet.
  OpenStreetMap and Satellite were never affected. A key is free up to
  5 million tile requests per calendar month:

      https://carto.com/basemaps/apikey/

  You get:

  - A key field under Admin -> Live Map, handled like the OpenWeatherMap
    key: empty keeps the stored key, a checkbox clears it. The stored
    value is never pre-filled into the form.
  - Its own "Basemap" section, no longer squeezed under "Weather".
  - A status box that separates three things: is a key stored, does CARTO
    actually accept it, and is the default basemap a CARTO style at all.
    The verdict is stored, not re-fetched on every page load.
  - The key is appended once where the tile layer is created, so any CARTO
    style added later is covered automatically.
  - A fallback to CARTO_API_KEY in .env, so the key can be in place before
    anyone opens the settings page.

  The key is checked by comparing images, not status codes: CARTO answers
  every tile request with HTTP 200 - no key, wrong key, empty key alike,
  with identical headers. Only the image differs. A wrong key would
  otherwise stay invisible until someone opens the map.

  Without a key nothing breaks - the map still loads, it just carries
  the watermark.

  Keep the CARTO and OpenStreetMap attribution visible; that is the
  condition of the free tier.

Older fixes still included:
  (v4.7.6) Live Map settings no longer appear a second time in the core
           settings page.
  (v4.7.5) A brand-new OpenWeatherMap key can be saved even while OWM
           still answers 401 during its activation window.
  (v4.6.7) View paths are only registered when they exist, so
           `php artisan view:cache` no longer throws.
  (v4.6.6) Mixed-content warnings silenced (HTTPS upgrade).
  (v4.6.5) Settings persist in the phpVMS database.

Installation and update (FTP + phpVMS admin, no SSH)
=====================================================

You need: an FTP client (FileZilla, WinSCP, Cyberduck ...) or the file
manager of your hosting panel, and an admin login to phpVMS.

<phpvms-root> below is the phpVMS folder on your server: the one that
contains .env, app/, modules/ and resources/. On some hosts it is the web
root itself, on others a sub folder (for example httpdocs/phpvms).

Unpack the ZIP on your computer first. You get:
  LiveMap/              the module
  live_map.blade.php    the theme file (one line)
  INSTALL.txt           this file

1) Upload the module folder - UPLOAD FIRST, SWAP LAST

   !! Do NOT delete or overwrite the live LiveMap/ folder while the site
      is running. If module.json is in place before Providers/ has
      finished uploading, phpVMS finds the module, tries to load
      Modules\LiveMap\Providers\LiveMapServiceProvider, cannot, and
      throws a fatal error on EVERY page - including /admin. You are
      then locked out of your own site until you fix it from the
      database (see "If your site is down" below).

      This is not theoretical: it happened to a VA on 27 Aug 2026,
      following the older wording of this very file. That wording was
      ours, and it was wrong.

   Do this instead - the swap is a rename, which takes milliseconds:

     a) Upload/extract the LiveMap/ folder from this ZIP as
          <phpvms-root>/modules/LiveMap_new/
        (phpVMS only scans folders that contain a module.json AND are
        registered; a folder under a different name is inert)
     b) Verify the upload is complete. These must exist:
          modules/LiveMap_new/module.json
          modules/LiveMap_new/Providers/LiveMapServiceProvider.php
          modules/LiveMap_new/Http/Controllers/Admin/SettingsController.php
     c) Rename modules/LiveMap  ->  modules/LiveMap_old
        (first install: there is no modules/LiveMap yet - skip this)
     d) Rename modules/LiveMap_new  ->  modules/LiveMap
     e) Delete modules/LiveMap_old once the site is confirmed working

   First install only: Admin -> Modules. LiveMap is listed under
   "Not Installed Modules" - click "Activate Module".

   If your site is down with "LiveMapServiceProvider not found":

     In phpMyAdmin, table `modules`, row where name = 'LiveMap':
     set `enabled` from 1 to 0. The site comes back immediately.
     Then finish the upload properly and set it back to 1.

2) Upload the theme file into EVERY theme your site uses

   Which theme is active: Admin -> Settings -> General -> "Current Theme".
   If pilots can pick other themes, or you keep a second theme for
   testing, do this for those as well. It does no harm in an unused theme.

   phpVMS draws the map wherever a theme page calls {{ Widget::liveMap() }}
   - in every standard theme that is the page /livemap ("Live Map" in the
   menu). phpVMS takes the file widgets/live_map.blade.php from the
   active theme. Our file in that place hands everything over to the
   module, so the map looks and works the same in every theme.

   Upload live_map.blade.php with FTP to the theme's widgets folder and
   overwrite the file that is there:

     Theme           Upload to
     -------------   -----------------------------------------------------
     seven           <phpvms-root>/resources/views/layouts/seven/widgets/
     SPTheme         <phpvms-root>/resources/views/layouts/SPTheme/widgets/
     Disposable_v3   <phpvms-root>/resources/views/layouts/Disposable_v3/widgets/
     default / beta  <phpvms-root>/resources/views/layouts/beta/widgets/
                     ("default" is only an alias of "beta")
     any other       <phpvms-root>/resources/views/layouts/<Theme>/widgets/

   - The folder name must match exactly, including upper and lower case
     (SPTheme, Disposable_v3).
   - The file name must be exactly live_map.blade.php.
   - No widgets/ folder in that theme? Create it, then upload the file.
   - Themes that extend another theme (theme.json, "extends") still get
     their own copy: put the file into the theme you actually use.
   - Then delete these two old files in the same widgets/ folder, if they
     are there (not used from 5.1 on):
       live_map_scripts.blade.php
       live_map_styles.blade.php

   Want the map on another page too (for example the dashboard)? Put
   {{ Widget::liveMap() }} into that page of your theme.

3) Clear the caches
   Admin -> Maintenance -> "Clear all caches".
   Use "all": it also rebuilds a cached route list. Without it the map
   can stay empty (the flight data address answers 404).

4) Settings
   Admin -> Live Map. Open it once and click Save.
   - Source: phpVMS. (AeroACARS Live is for German Sky Group only.)
   - OpenWeatherMap key: paste it, or leave it empty - the map then just
     shows no weather.
   - Keep "server-side weather proxy" ON (the key never reaches the
     browser).
   - Flights list: "Bottom" is recommended. An update from 4.7.x keeps
     its old position (top or off) until you change it here.
   - Accent colour for light and dark mode, so the map matches your site.
   The page opens for every user with admin panel access (role "admin" or
   the permission "Admin Panel").

5) Check
   Open https://<your-site>/livemap and hard-refresh (Ctrl+F5, on a Mac
   Cmd+Shift+R). The map, the flights list below it and the credit line
   under the map must appear. Check every theme you uploaded to.

Troubleshooting:
  "Settings reset every day"        -> upgrade to v4.6.6.
  "Map loads and loads and loads"   -> upgrade to v5.1 (no theme scripts any
                                       more) or redeploy all three old widget files.
  "Mixed-content warnings"          -> this release includes the HTTPS upgrade patch.
  "Weather Proxy: API Key Missing"  -> paste key in Admin -> Live Map, Save.
  "CARTO key will not save/delete"  -> upgrade to v4.7.2, then enter it again.
  "OpenWeatherMap rejected the key" -> a NEW OWM key returns 401 for up to
                                       two hours until it activates. From
                                       v4.7.5 the key is saved anyway and
                                       the status box re-checks it.
  "LiveMapServiceProvider not found" -> partial upload. See step 1 and the
                                       database recovery above.
  "Settings page throws HTTP 500"   -> upgrade to v4.7.2.
  "Aircraft parked at 0/0 / progress
   stuck at 100% / map zoomed out"  -> upgrade to v4.7.7. The sim has not
                                       reported a position yet; the map
                                       now ignores 0/0 instead of drawing
                                       it.
